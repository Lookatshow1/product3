# CallFlow OS — Чеклист комплаенса

## 1. Классификация данных

### Что НЕЛЬЗЯ хранить (никогда)

| Тип данных | Причина | Что делать |
|-----------|---------|-----------|
| Медицинские диагнозы пациентов | ФЗ-323, врачебная тайна | Не собирать, не принимать в CSV |
| Данные медкарт | ФЗ-323 | Не собирать |
| Паспортные данные | ФЗ-152 (избыточный сбор) | Не собирать |
| Данные банковских карт | PCI DSS | Не собирать, биллинг через провайдера (Stripe/ЮKassa) |
| Пароли в открытом виде | Базовая безопасность | Только bcrypt hash |

### Что МОЖНО хранить (режим "обезличенный" — по умолчанию)

| Тип данных | Пример | Основание |
|-----------|--------|-----------|
| Агрегированные метрики | "87 звонков, 68 принятых, 34 записи" | Не являются ПДн |
| Дата/время обращения | "2025-01-15 09:32" | Без привязки к личности |
| Канал обращения | "phone_in" | Техническая метрика |
| Статус обращения | "answered", "missed" | Техническая метрика |
| Длительность | 180 сек | Техническая метрика |
| Результат | "booked", "not_booked" | Бизнес-метрика |
| Причина отказа | "high_price" | Бизнес-метрика, без привязки к личности |
| Имя оператора | "Иванова А.С." | Трудовые отношения (ст. 86 ТК РФ) |
| Обезличенный ID | "hash_abc123" | Не ПДн если невозможно деанонимизировать |

### Что МОЖНО хранить ТОЛЬКО в режиме "персональный" (с согласия)

| Тип данных | Требования | Шифрование |
|-----------|-----------|-----------|
| Телефон пациента | Согласие на обработку ПДн | AES-256 (application-level) |
| Имя пациента | Согласие на обработку ПДн | AES-256 |
| Аудиозаписи звонков | Согласие + уведомление о записи | Шифрование at rest (S3 SSE) |
| Транскрипции звонков | Согласие на обработку ПДн | AES-256 |

## 2. Режимы приватности

### Режим "Обезличенный" (по умолчанию)

```
✅ Включён по умолчанию при создании клиники
✅ Персональные поля при импорте CSV: игнорируются / хешируются
✅ Задачи: "Перезвонить (задача #47)" — без номера телефона
✅ Дашборд: только агрегаты
✅ Отчёты: только агрегаты
```

При загрузке CSV с персональными данными в обезличенном режиме:
1. Система детектирует колонки с телефонами/именами
2. Показывает предупреждение: "Обнаружены персональные данные (колонка 'Телефон'). В режиме 'обезличенный' эти данные не будут сохранены. Для сохранения переключитесь в режим 'с персональными данными'."
3. Колонки с ПДн пропускаются (не сохраняются) — ИЛИ хешируются (SHA-256 + salt) для дедупликации

### Режим "С персональными данными"

Переключение:
1. Настройки → Данные и приватность → Режим: "С персональными данными"
2. Чекбокс: "Подтверждаю, что клиника получила согласие субъектов ПДн на обработку данных в соответствии с ФЗ-152"
3. Чекбокс: "Подтверждаю, что уведомление Роскомнадзора подано (или не требуется)"
4. Текст согласия (шаблон предоставляется)
5. [Включить персональный режим]

В персональном режиме:
```
✅ Телефоны и имена сохраняются (зашифрованы AES-256)
✅ Задачи содержат контактную информацию
✅ Возможен поиск по пациенту
✅ Аудиозаписи привязываются к контактам
⚠️ Audit log фиксирует каждый доступ к ПДн
⚠️ Данные можно удалить по запросу субъекта
```

## 3. Обезличивание данных

### Алгоритм при импорте (режим "обезличенный")

```python
def anonymize_import(row, salt):
    # Телефон → hash (для дедупликации, но не деанонимизации)
    if row.get('patient_phone'):
        row['patient_id'] = sha256(row['patient_phone'] + salt).hex()[:16]
        del row['patient_phone']

    # Имя → удалить
    if row.get('patient_name'):
        del row['patient_name']

    # Оператор — оставить (это сотрудник, не пациент)
    # row['operator_name'] остаётся

    return row
```

### Обезличивание аудио (V1)

Для аудиозаписей в обезличенном режиме:
1. Транскрипция выполняется
2. Из транскрипции удаляются:
   - Телефонные номера (regex: `\+?[78]\d{10}`)
   - Имена собственные (NER — именованные сущности)
   - Адреса
3. Аудио-файл удаляется после транскрипции (хранится только обезличенный текст)
4. Можно отключить транскрипцию полностью

## 4. Удаление данных

### По запросу субъекта ПДн (один пациент)

Если клиника в персональном режиме и получила запрос на удаление:

1. Настройки → Данные → "Удалить данные пациента"
2. Поиск по телефону или patient_id
3. Система находит все связанные записи:
   - call_records (с этим patient_id / patient_phone)
   - tasks (связанные с этими call_records)
   - Аудиозаписи
   - Транскрипции
4. Hard delete всех записей
5. Audit log: "Удалены данные субъекта ПДн по запросу, operator: admin@clinic.ru, count: 15 records"

### Удаление всех данных клиники

1. Настройки → Данные → "Удалить все данные"
2. Подтверждение: ввести название клиники
3. Удаляется:
   - ✅ Все call_records
   - ✅ Все daily_funnels
   - ✅ Все daily_losses
   - ✅ Все tasks
   - ✅ Все anomalies
   - ✅ Все reports (файлы из S3 + записи в БД)
   - ✅ Все аудиозаписи (S3 + записи)
   - ✅ Все imports
   - ✅ Все notifications
4. Не удаляется:
   - ❌ Пользователи и роли (для возможности повторного использования)
   - ❌ Настройки клиники
   - ❌ Audit log (сохраняется для комплаенса)
5. Audit log: "Полное удаление данных клиники clinic_id=xxx, operator: owner@clinic.ru"

### Удаление организации

1. Только owner может удалить
2. Удаляет всё: организацию, клиники, пользователей, все данные
3. Необратимо
4. Отправляет confirmation email

## 5. Хранение и TTL

| Тип данных | TTL (по умолчанию) | Настраиваемо |
|-----------|-------------------|-------------|
| call_records | Без лимита (по тарифу: 6/24/∞ мес) | Да |
| daily_funnels | Без лимита (по тарифу) | Да |
| daily_losses | Без лимита (по тарифу) | Да |
| tasks | 90 дней после закрытия | Да |
| anomalies | 180 дней | Да |
| Аудиозаписи | 90 дней | Да (30–365 дней) |
| Транскрипции | 180 дней | Да |
| PDF-отчёты | 365 дней | Да |
| Audit log | 365 дней (минимум) | Нет (фиксированно) |
| Import файлы (оригиналы CSV) | 30 дней | Нет |

Cron-задача `cleanup-expired-data` запускается ежедневно в 03:00 UTC.

## 7. Согласия и документы

### Шаблоны (предоставляются клинике)

1. **Согласие на обработку ПДн** — шаблон для пациента (для подписания в клинике)
2. **Политика конфиденциальности CallFlow OS** — публичный документ
3. **Пользовательское соглашение (Terms of Service)** — публичный документ
4. **DPA (Data Processing Agreement)** — соглашение об обработке данных между CallFlow и клиникой
5. **Инструкция по подаче уведомления в Роскомнадзор** — если клиника обрабатывает ПДн

### Ответственность

```
CallFlow OS = Обработчик ПДн (процессор)
Клиника = Оператор ПДн (контроллер)

CallFlow OS:
- Обрабатывает данные только по поручению клиники
- Не передаёт данные третьим лицам
- Обеспечивает техническую защиту
- Удаляет данные по запросу

Клиника:
- Получает согласия от пациентов
- Определяет цели обработки
- Подаёт уведомление в РКН (если требуется)
- Отвечает на запросы субъектов ПДн
```
