# CallFlow OS — Definition of Done (Приёмка)

## Критерии MVP Ready

### Критерий 1: "CSV → Потери за 10 минут"

**Сценарий:**
1. Новый пользователь регистрируется (email + пароль)
2. Заполняет онбординг: тип клиники, средний чек, кол-во кресел
3. Загружает CSV-файл из АТС (87 строк, формат: дата/время, статус, результат, оператор)
4. Система автодетектирует разделитель, кодировку, формат даты
5. Пользователь маппит колонки (drag-and-drop или dropdown)
6. Нажимает "Импортировать"
7. Через <10 секунд видит дашборд с:
   - 4 карточки потерь (в рублях)
   - Воронка дня
   - Топ-5 утечек с рекомендациями
   - Прогноз возврата (3 сценария)

**Проверка:** Весь путь от регистрации до "вау"-дашборда ≤ 10 минут.

**Альтернативный путь:** Вместо CSV пользователь вводит 5–10 чисел (воронка дня) → результат тот же за 2 минуты.

### Критерий 2: "План дня работает"

**Сценарий:**
1. После импорта данных система автоматически генерирует задачи
2. На экране "План дня" пользователь видит:
   - Группы задач: перезвоны, подтверждения, удержание, дожим
   - Количество задач в каждой группе
   - Дедлайны
   - Прогресс-бар
3. Пользователь отмечает задачу как "выполнено" / "перенесено" / "неактуально"
4. Прогресс-бар обновляется мгновенно
5. В агрегированном режиме (без персданных): пакетная отметка работает

**Проверка:** Задачи генерируются корректно из данных. Статусы сохраняются. Прогресс считается.

---

### Критерий 3: "Уведомления приходят"

**Сценарий:**
1. В настройках клиники включены email-дайджесты
2. В 08:30 (по TZ клиники) приходит утренний дайджест:
   - Тема: "🔴 CallFlow: потери вчера XX ₽, план на сегодня"
   - Тело: потери, топ-3 утечки, план задач, ссылка в приложение
3. В 12:30 приходит midday nudge (если прогресс <50%)
4. В 20:30 приходит вечерний отчёт: факт/план
5. In-app уведомления показываются в колокольчике

**Проверка:** Все 3 email приходят вовремя (±5 минут). Содержат корректные данные. Ссылки работают.

---

### Критерий 4: "Задачи отмечаются, прогресс виден"

**Сценарий:**
1. Утром сгенерировано 67 задач (23 перезвона, 15 подтверждений, 4 удержания, 8 дожимов, 17 прочих)
2. В течение дня оператор/админ отмечает задачи
3. Прогресс-бар: 0% → 51% → 89%
4. Невыполненные задачи → красный индикатор
5. В вечернем отчёте: "Выполнено 60 из 67 (89%)"

**Проверка:** Все статусы работают, прогресс пересчитывается, вечерний отчёт содержит факт.

---

### Критерий 5: "Отчёт формируется"

**Сценарий:**
1. Пользователь (роль: manager/owner) переходит в "Отчёты"
2. Выбирает период, тип (для собственника), формат PDF
3. Нажимает "Сгенерировать"
4. Через <5 секунд отчёт готов к скачиванию
5. PDF содержит: 4 ключевые цифры, воронку, топ-3 проблемы, сравнение с бенчмарком

**Проверка:** PDF генерируется, открывается, содержит корректные данные, помещается на 1 страницу.

---

### Критерий 6: "Роли работают, данные разделены"

**Сценарий:**
1. Owner создаёт организацию с 2 филиалами
2. Приглашает manager для филиала А и operator для филиала Б
3. Manager филиала А видит только данные филиала А
4. Operator видит только свои задачи и свои KPI
5. Owner видит все филиалы и все данные

**Проверка:**
- Manager не может видеть данные другого филиала (API возвращает 403)
- Operator не может видеть дашборд и KPI других
- Owner видит всё, включая billing

---

### Критерий 7: "Удаление данных работает"

**Сценарий:**
1. Owner переходит в Настройки → Данные и приватность
2. Нажимает "Удалить все данные клиники"
3. Вводит название клиники для подтверждения
4. Все call_records, daily_funnels, tasks, anomalies, reports, аудиофайлы удаляются
5. Настройки клиники и пользователи остаются

**Проверка:**
- Данные удалены из БД (не soft delete, а hard delete)
- Аудиофайлы удалены из S3
- Audit log зафиксировал действие
- Дашборд показывает пустое состояние

---

### Критерий 8: "Демо-данные впечатляют"

**Сценарий:**
1. При онбординге пользователь выбирает "Использовать демо-данные"
2. Система загружает 30 дней реалистичных данных
3. Дашборд сразу показывает "вау": потери ~200 000 ₽/мес, тренды, утечки
4. План дня содержит задачи
5. Операторы с разными KPI (хороший, средний, плохой)
6. Есть аномалии

**Проверка:** Демо-данные создают "вау"-момент за 30 секунд после выбора.

## Чеклист технического качества

| # | Требование | Как проверить |
|---|-----------|---------------|
| 1 | Дашборд загружается <2 сек | Lighthouse Performance >80 |
| 2 | CSV 5000 строк обрабатывается <10 сек | Benchmark test |
| 3 | PDF генерируется <5 сек | Timer в логах |
| 4 | Нет SQL injection, XSS | Prisma (parameterized), React (auto-escape) |
| 5 | Пароли хешируются (bcrypt) | Проверка БД |
| 6 | JWT ротация работает | Тест: expired token → refresh → new token |
| 7 | RLS включён для всех таблиц с данными | SQL audit |
| 8 | Файлы загружаются в S3, не в локальную FS | Проверка storage |
| 9 | Email отправляется (не в спам) | SPF/DKIM настроены, тест |
| 10 | Responsive layout на мобильном | Chrome DevTools 375px |
| 11 | Часовые пояса корректны | Тест: клиника в UTC+5, проверить время дайджеста |
| 12 | Windows-1251 CSV парсится | Тест с файлом из стандартной АТС |
